# Описание проекта DialogMTEB

## Аннотация

Проект DialogMTEB направлен на расширение языкового покрытия диалоговых задач для оценки моделей векторных представлений текста. Такие модели используются в чат-ботах, ассистентах, поиске по истории диалогов, классификации намерений, подборе и повторном ранжировании ответов, поэтому качество их работы важно проверять не только на одиночных текстах, но и на данных с диалоговым контекстом.

Базовые наборы оценки, включая [MTEB](https://arxiv.org/abs/2210.07316), покрывают широкий круг задач, но диалоговые сценарии остаются отдельной сложной областью. В диалоге модель должна учитывать историю, неполные реплики, кореференцию, прагматику, многозначность пользовательского запроса и связь между несколькими сообщениями. Кроме того, многие открытые диалоговые наборы данных доступны прежде всего на английском языке, что ограничивает сравнимую оценку многоязычных моделей векторных представлений.

Цель командной работы - подготовить воспроизводимую основу для многоязычного DialogMTEB: перевести набор диалоговых данных на русский и французский языки, сохранить исходные схемы задач и опубликовать артефакты так, чтобы ими могли пользоваться другие исследователи. Важной частью работы было не только получение переводов, но и контроль того, что перевод не разрушает схему задачи, разбиения, идентификаторы, метки, связи релевантности и специальные структурные поля.

В проекте были реализованы два взаимодополняющих направления. Русскоязычная часть опиралась на интерактивные исследовательские сценарии, Yandex Translator и оценку качества перевода с помощью языковой модели. Франкоязычная часть была оформлена как отдельный пакет `data-translate` с командами для терминала, YAML-настройками наборов данных, стратегиями перевода, статическими проверками, экспортом в parquet и загрузкой готовых наборов данных в организацию Hugging Face `DeepPavlov`.

Практический результат проекта - открытые репозитории с кодом и документацией, публичные наборы данных на Hugging Face, презентация для защиты и зафиксированное распределение вклада в команде. Это превращает перевод наборов данных из ручного набора скриптов в воспроизводимый конвейер, который можно расширять на новые данные, языки и методы проверки качества.

## Проблематика

Модели векторных представлений активно используются в современных системах обработки естественного языка, но их качество на диалоговых задачах сложнее оценивать, чем на обычных задачах уровня предложения или документа. Диалоговые данные содержат историю взаимодействия, роли участников, структурные поля действий, ссылки, файлы, идентификаторы и разметку, которую нельзя переводить как обычный текст.

Если переводить такие наборы данных вручную или разрозненными скриптами, возникает несколько рисков: меняется число строк в разбиениях, теряются поля, ломаются списки реплик, переводятся служебные значения, нарушаются связи релевантности или последовательности действий. В результате формально переведенный набор данных может стать непригодным для честной оценки моделей векторных представлений.

## Постановка задачи

Исследовательский вопрос проекта: можно ли расширить DialogMTEB на новые языки через автоматический перевод и контроль качества так, чтобы сохранить сопоставимость исходных задач?

В рамках этой постановки были выделены практические задачи:

- перевести набор диалоговых данных на русский и французский языки;
- сохранить исходные разбиения, схемы, метки, идентификаторы, связи релевантности и специальные поля задач;
- разработать проверки, которые находят структурные ошибки и подозрительные переводы до публикации;
- оформить результаты как открытые артефакты: репозитории GitHub, README, Slidev-презентация и наборы данных Hugging Face;
- зафиксировать роли участников команды и воспроизводимый процесс работы.

## Описание технического решения

Русскоязычная часть проекта велась в репозитории [interpparietes/DialogMTEB](https://github.com/interpparietes/DialogMTEB). В ней использовались интерактивные исследовательские сценарии `translator_yandex_*`, перевод через Yandex Translator и оценка качества через `LLM_Evaluation.ipynb`. Языковая модель проверяла качество по нескольким критериям: точность и полнота смысла, грамматика и орфография, естественность и стиль.

Франкоязычная часть оформлена в репозитории [IsachenkoBogdan/data-translate](https://github.com/IsachenkoBogdan/data-translate). Пакет `data-translate` содержит команды для перевода, проверки, оценки, экспорта и загрузки наборов данных. Логика отдельных наборов данных вынесена в YAML-настройки `conf/datasets`, а правила публикации - в `conf/uploads`.

Ключевая схема конвейера:

```text
описание набора
  -> стратегия перевода
  -> переведенный результат
  -> check-translation
  -> экспорт parquet
  -> загрузка в Hugging Face
```

Для разных типов данных используются разные стратегии перевода: простые текстовые поля, списки реплик, диалоговые ходы, вложенные структуры и стратегия `deep_map`, которая переводит все текстовые значения внутри ячейки. Отдельные защитные правила сохраняют технические значения: ссылки, имена файлов, пути, почтовые адреса, похожие на хеши идентификаторы, вложения и служебный синтаксис действий.

Модуль `check-translation` выполняет проверки перед загрузкой. Он проверяет совпадение числа строк и разбиений, наличие переведенных полей, пустые переводы, длины списков, подозрительно неизмененный английский текст, корректность последовательности действий WebLINX и проблемы соответствия строк на примере DailyDialog. Ложные предупреждения для технических строк подавляются отдельно, чтобы отчет фокусировался на реальных рисках перевода.

## Дальнейшие планы по развитию

Дальнейшая работа состоит из нескольких направлений:

- расширить ручную проверку качества на самые крупные поисковые наборы;
- добавить ручную двуязычную проверку на небольшой выборке из диалогового домена;
- добавить второй уровень проверки с помощью языковой модели для подозрительно непереведенного текста;
- интегрировать переведенные наборы данных в полноценную многоязычную оценку DialogMTEB;
- расширить конвейер на новые языки и новые типы диалоговых задач;
- подготовить результаты как открытый артефакт набора оценки для дальнейших исследований и возможной публикации.
